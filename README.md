# Антирейтинг — чат-бот в MAX для тренировки русского языка

**Трек:** «Образовательные решения», VK MAX 2026
**Тип решения:** чат-бот (без мини-приложения, без собственного API)
**Ссылка на работающее решение:** https://max.ru/t458_hakaton_max_bot

---

## 1. Назначение решения

Чат-бот тренирует школьников 6–11 классов и студентов СПО/вуз по трём темам по русскому языку — орфоэпия, словарные слова, пунктуация — и строит для каждого пользователя личный список «слабых мест».

Ключевая механика: за каждый ответ обновляется вес элемента (слова, словарного слова, пунктуационного правила) в базе по единому правилу — верный ответ снижает вес на `3`, ошибка повышает на `5`. В пунктуации вес меняется у каждого правила, отвечающего за позицию в предложении. Подбор заданий идёт по убыванию веса, поэтому следующая тренировка начинается с того, что пользователь уже не освоил. Раздел «Мои сложные …» показывает до 10 элементов с наибольшим весом — это персональный антирейтинг.

Пользовательский результат: рост доли полностью верных ответов за сессию и уменьшение числа повторных ошибок на одних и тех же словах и правилах.

## 2. Основной пользовательский сценарий

Сценарий одинаков для всех трёх разделов и проходит целиком в чате MAX (мобильная и веб-версия).

1. Пользователь открывает чат-бота и отправляет `/start`. Бот создаёт запись пользователя и показывает главное меню: «🗣 Орфоэпия», «📝 Словарные слова», «✍️ Пунктуация».
2. Пользователь выбирает раздел. Бот открывает меню раздела: «🧠 Тренировка», «📕 Мои сложные …», «🔙 Назад».
3. **Орфоэпия.** Бот выводит слово заглавными буквами и кнопки-варианты с разной прописной гласной (по одной на каждую гласную). Пользователь нажимает вариант. Бот отвечает «✅ Верно!» или «❌ Ошибка!», показывает правильное написание и сразу следующий вопрос. Если в слове нет гласных, предлагается единственный вариант.
4. **Словарные слова.** Бот выводит слово с пропусками (`аб..жур`) и кнопки с вариантами написания, перемешанными случайно. Пользователь нажимает вариант, получает разбор и следующий вопрос.
5. **Пунктуация.** Бот выводит предложение с пронумерованными позициями и просит отправить номера позиций, где нужна запятая, слитно (например `125`). Пользователь отправляет текстом цифры. Бот отвечает «✅ Верно!» или «❌ Ошибка!» и показывает эталонную расстановку. Кнопки «📖 Подробнее» (разбор по каждой позиции с текстом правила), «➡️ Следующее» (новое предложение) и «🛑 Закончить» (итоги сессии).
6. **Сложные элементы.** Кнопка «📕 Мои сложные …» выводит персональный антирейтинг: до 10 слов или правил с наибольшим положительным весом. До первой тренировки или отрицательных весов показывается сообщение «Пока не выявлено трудных слов / правил».
7. **Итоги.** Кнопка «🛑 Закончить» (либо конец подборки) выводит блок «🏁 Тренировка завершена!» с числом пройденных элементов, числом верных ответов, списком ошибок и подтверждением обновления статистики.
8. Кнопка «🔙 Назад» возвращает в меню раздела, из него — в главное меню.

Ошибки обрабатываются на месте: неверный формат ответа в пунктуации — подсказка о формате; позиция, которой нет в предложении, — перечень доступных позиций; повторный ответ на уже засчитанное предложение — просьба нажать «➡️ Следующее»; сбой обновления статистики в орфоэпии и словарных словах — сообщение «Не удалось обновить статистику тренировки» с возможностью начать заново. Полный перезапуск решения после ошибки не требуется.

## 3. Состав и архитектура решения

### Компоненты (docker compose)

| Сервис     | Образ                                         | Роль                                                                 |
|------------|-----------------------------------------------|----------------------------------------------------------------------|
| `maxbot`   | собирается из `Dockerfile` (`node:22-alpine`) | чат-бот: long polling к MAX Bot API, бизнес-логика, работа с БД      |
| `database` | `postgres:17-alpine`                          | хранение данных и персональной статистики, автоинициализация дампами |
| `adminer`  | `adminer:4.8.1`                               | служебный веб-интерфейс просмотра БД                                 |
| `backup`   | `postgres:17-alpine'                          | делает бекапы БД                                                     |


### Слои кода

```
apps/bot/main.ts                 точка входа: инициализация БД, регистрация хендлеров, long polling
apps/bot/src/handlers/           обработчики событий: start, menu, orthoepy, vocabularies, punctuation
apps/bot/src/constants/          callback-идентификаторы и regex-паттерны действий
apps/bot/src/keyboards/          inline-клавиатуры
apps/bot/src/texts/              сборка текстов ответов
apps/bot/src/*-service.ts        предметная логика: сессии, веса, подбор, проверка ответов
apps/bot/src/user-service.ts     регистрация пользователя по MAX user_id
apps/assets/text/                константы текстов интерфейса
apps/database/db_engine.ts       подключение: postgres.js (запросы) + Prisma Client через pg-адаптер
apps/database/schema.ts          подключение Prisma при старте
apps/utils/env.ts                чтение переменных окружения через dotenv
prisma/schema.prisma             схема данных
prisma/migrations/               миграции 0001–0004
database/dumps/                  подготовленные данные (тестовые)
scripts/baseline-database.mjs    приведение существующей БД к истории миграций
```

Алиасы `@bot`, `@database`, `@utils`, `@assets` заданы в `tsconfig.app.json` и `vite.config.ts`.

### Модель данных

| Таблица | Содержимое |
| --- | --- |
| `users` | `id` — числовой идентификатор пользователя MAX |
| `orthoepy` | слова с ударением (заглавная гласная) |
| `orthoepy_wt` | персональный вес слова |
| `vocabularies` | слово с пропусками + массив вариантов написания |
| `vocabularies_wt` | персональный вес словарного слова |
| `punctuation_rules` | тексты правил пунктуации |
| `punctuation_tasks` | предложение с маской позиций, эталонные позиции, JSON-разбор по правилам |
| `user_rule_weights` | персональный вес пунктуационного правила |

Сессия тренировки (текущее слово, прогресс, ошибки) хранится в памяти процесса бота; в БД попадают только веса.

## 4. Запуск всех локальных компонентов одной командой

```bash
docker compose up -d --build
```

Требуется предварительно создать `.env` из `.env.example` и вписать `BOT_TOKEN`, `DB_USER`, `DB_PASS`, `DB_NAME` (см. раздел 5). Команда поднимает БД, прогоняет автоинициализацию дампами, применяет миграции и запускает бота.

## 5. Переменные окружения

Файл `.env` создаётся из `.env.example`. Рабочие значения в репозитории отсутствуют.

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | да | токен чат-бота, выдаётся организаторами; без него бот не стартует |
| `DB_USER` | да | пользователь PostgreSQL; compose прерывает запуск, если не задан |
| `DB_PASS` | да | пароль PostgreSQL |
| `DB_NAME` | да | имя базы PostgreSQL |
| `DB_HOST` | нет | `docker-compose.yml` переопределяет на `database`; для локального запуска вне Docker — `localhost` |
| `DB_PORT` | нет | порт PostgreSQL; compose переопределяет на `5432` внутри сети, наружу публикуется значение этой переменной |
| `DB_SCHEME` | нет | `docker-compose.yml` переопределяет на `postgres`; в `.env.example` — `postgresql` |
| `DATABASE_URL` | нет | переопределяет строку подключения целиком; если пусто, собирается из `DB_*` |
| `ADMINER_PORT` | нет | порт Adminer снаружи контейнера, по умолчанию `8080` |
| `DB_COLLATE` | нет | объявлен в `.env.example`, в коде не используется |

## 6. Используемые порты

| Порт | Компонент | Назначение |
| --- | --- | --- |
| `DB_PORT` (по умолчанию `5432`) | `database` | прямой доступ к PostgreSQL с хоста |
| `ADMINER_PORT` (по умолчанию `8080`) | `adminer` | веб-интерфейс просмотра БД |

Бот входящих портов не имеет: работает на long polling к MAX Bot API, HTTP-сервер не поднимается. Внешний HTTPS-адрес решения отсутствует — собственного API у решения нет.

## 7. Зависимости

Сборка образа `maxbot` (`node:22-alpine`): `npm ci --legacy-peer-deps` (`package-lock.json` фиксирует версии; флаг дублирует `.npmrc`), затем `npx prisma generate`.

Прямые зависимости (`dependencies`): `@maxhub/max-bot-api` — API чат-ботов MAX; `@prisma/client`, `@prisma/adapter-pg`, `prisma` — доступ к БД и миграции; `postgres` — исполнение SQL-запросов; `pg` — драйвер для адаптера Prisma; `dotenv` — переменные окружения; `vite` — конфигурация веб-сборки, в решении не используется (веб-приложения в репозитории нет). Зависимости разработки (`devDependencies`): `typescript`, `tsx`, `eslint` и плагины (`@eslint/js`, `typescript-eslint`, `eslint-plugin-react`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `globals`), `@vitejs/plugin-react`, `@types/node`.

Внешние ресурсы на этапе сборки: реестр npm, базовые образы `node:22-alpine`, `postgres:17-alpine`, `adminer:4.8.1`. Docker-конфигурация содержит только компоненты, необходимые для запуска; целевое время сборки — не более 5 минут без учёта первоначальной загрузки базовых образов.

TLS: в образе подключается российский корневой сертификат `certs/russian-trusted-root-ca.crt` через `NODE_EXTRA_CA_CERTS`; пакет `openssl` доустанавливается в образ.

## 9. Работа с данными

**Происхождение данных.** Все три набора — заранее подготовленные SQL-дампы в `database/dumps/`, а не данные реальных информационных систем. Это модельные данные.

| Файл | Содержимое | Объём |
| --- | --- | --- |
| `database/dumps/orthoepy.sql` | слова с отмеченным ударением | 192 слова |
| `database/dumps/vocabularies.sql` | задания на написание слова | 512 заданий |
| `database/dumps/punctuation.sql` | правила и предложения с разбором | 15 правил, 26 предложений |

**Когда применяются.** Каталог `database/dumps` смонтирован в `/docker-entrypoint-initdb.d` контейнера `database`, поэтому дампы выполняются только при первом старте на пустом томе. На существующем томе данные не перезагружаются.

**Схема и миграции.** `prisma/schema.prisma`; миграции `0001_legacy_orthoepy_rename`, `0002_init`, `0003_vocabularies_training`, `0004_punctuation_training` применяются командой `prisma migrate deploy` при старте контейнера `maxbot`. `scripts/baseline-database.mjs` на случай БД с таблицами без истории миграций помечает `0001_legacy_orthoepy_rename` как применённую.

**Персональные данные.** В таблице `users` хранится только числовой `user_id` из MAX. Имя, телефон, email, геолокация и иные идентификаторы не собираются и не передаются. Персональные данные несовершеннолетних в объёме решения не используются. Запись пользователя создаётся при первом обращении; веса для всех элементов раздела создаются при первом входе в него и каскадно удаляются вместе с пользователем.

**Алгоритм накопления весов.** Начальный вес — `0`. Во всех трёх разделах действует одно правило: верный ответ снижает вес на `3`, ошибка повышает на `5`. Орфоэпия и словарные слова меняют вес элемента (`orthoepy_wt`, `vocabularies_wt`); пунктуация — вес каждого правила, отвечающего за позицию в предложении (`user_rule_weights`), то есть веса обновляются у всех правил предложения. Элементы с весом `> 0` попадают в «Мои сложные …» и показываются первыми при подборе. Полностью верным ответом по предложению считается точное совпадение множества отправленных позиций с эталонными.

**Хранение сессий.** Прогресс текущей тренировки (номер вопроса, накопленные ошибки) хранится в памяти процесса бота и не сохраняется. Веса сохраняются в PostgreSQL и переживают перезапуск. Резервные копии создаются только сервисом `backup` из `docker-compose.prod.yml` (каждые 6 часов, глубина хранения 7 суток, каталог `./database/backups`).

## 10. Порядок работы с тестовыми данными

1. Создать `.env` из `.env.example`, заполнить `DB_USER`, `DB_PASS`, `DB_NAME`, `BOT_TOKEN`.
2. Выполнить `docker compose up -d --build`. Контейнер `database` применит дампы из `/docker-entrypoint-initdb.d` на пустом томе `postgres_data`; контейнер `maxbot` применит миграции и запустит бота.
3. Проверить, что данные загружены: открыть `http://localhost:8080`, войти под `DB_USER` / `DB_PASS`, база `DB_NAME`, и увидеть таблицы `orthoepy` (192), `vocabularies` (512), `punctuation_rules` (15), `punctuation_tasks` (26).
4. Перезагрузить данные: `docker compose down -v` (удаляет том `postgres_data`), затем `docker compose up -d --build` — дампы применятся заново.
5. Повторный импорт отдельных дампов вручную выполнять не следует: `orthoepy.sql` и `vocabularies.sql` содержат `DROP TABLE`, а на созданные миграциями таблицы весов ссылаются внешние ключи, поэтому импорт завершится ошибкой. `punctuation.sql` идемпотентен и может быть применён повторно.

## 11. Пошаговый сценарий проверки

Проверка выполняется в мессенджере MAX (мобильная или веб-версия) по ссылке https://max.ru/t458_hakaton_max_bot.

1. Открыть чат-бота, отправить `/start`. Ожидается приветствие и главное меню из трёх кнопок.
2. Нажать «🗣 Орфоэпия» → «🧠 Тренировка». Ожидается вопрос с заглавными буквами и кнопки-варианты ударения.
3. Нажать любой вариант. Ожидается «✅ Верно!» или «❌ Ошибка!», строка «Правильно: <слово>» и следующий вопрос без дополнительных команд.
4. Нажать «🛑 Закончить». Ожидается «🏁 Тренировка завершена!», счётчики «Пройдено слов» и «Верных ответов», список ошибочных слов.
5. Нажать «🔙 Назад» → «📕 Мои сложные слова». Ожидается список до 10 слов; если ошибок не было или все веса отрицательные — «Пока не выявлено трудных слов».
6. Вернуться в главное меню, нажать «📝 Словарные слова» → «🧠 Тренировка». Ожидается слово с пропусками и перемешанные кнопки написания. Пройти 3–5 вопросов, затем «🛑 Закончить» и проверить итоги.
7. Вернуться в главное меню, нажать «✍️ Пунктуация» → «🧠 Тренировка». Ожидается предложение с пронумерованными позициями.
8. Отправить в чат цифры слитно, например `12`. Ожидается «✅ Верно!» или «❌ Ошибка!», строка «Правильно: <предложение с запятыми>» и кнопки «📖 Подробнее», «➡️ Следующее», «🛑 Закончить».
9. Нажать «📖 Подробнее». Ожидается разбор по каждой позиции: «✅ Верно! Позиция N — запятая нужна» / «❌ Ошибка! Позиция N — запятая не нужна» и текст правила.
10. Отправить в чат некорректный ввод (например `1,3` или `абв`). Ожидается подсказка о формате, вопрос остаётся текущим.
11. Отправить позицию, которой нет в предложении. Ожидается перечень доступных позиций.
12. Нажать «➡️ Следующее» несколько раз, затем «🛑 Закончить». Ожидаются «🏁 Тренировка завершена!», «Пройдено предложений», «Полностью верных ответов», список правил, в которых были ошибки.
13. Проверить сохранение статистики: открыть «📕 Мои сложные правила» и убедиться, что ошибочные правила присутствуют в списке.
14. Перезапустить решение (`docker compose restart maxbot`), повторить шаги 5 и 13: список «сложных» сохранился, начатая тренировка сброшена.

## 12. Примеры ожидаемого поведения системы

**Главное меню** (после `/start`):
```
Привет! 👋 Я твой умный тренажер для подготовки к ЕГЭ и ОГЭ по русскому языку.
Моя фишка — алгоритм, который анализирует твои ответы. ...
Выбери раздел, чтобы начать тренировку:
[🗣 Орфоэпия] [📝 Словарные слова] [✍️ Пунктуация]
```

**Орфоэпия, вопрос** (кнопка-вариант строится для каждой гласной слова):
```
Выбери правильное ударение: КВАРТАЛ
[квАртал] [квартАл] [🛑 Закончить]
```

**Орфоэпия, верный ответ** (нажата кнопка `квартАл`, сообщение обновляется на месте):
```
✅ Верно!

Правильно: квартАл

Выбери правильное ударение: ЗНАЧИМОСТЬ
```

**Орфоэпия, ошибка** (в вопросе «Выбери правильное ударение: ЗНАЧИМОСТЬ» нажата кнопка `значИмость`):
```
❌ Ошибка!

Правильно: знАчимость

Выбери правильное ударение: КВАРТАЛ
```

**Словарные слова:** вопрос `Выбери корректное написание слово: аб..жур` с кнопками `абажур` / `абожур` в случайном порядке; после ответа — `✅ Верно!` или `❌ Ошибка!`, строка `Правильно: Абажур` и следующий вопрос.

**Пунктуация, вопрос:**
```
Расставь запятые. Отправь слитно номера позиций, где нужна запятая, без пробелов и знаков:
"На столе лежала книга (1) написанная известным автором (2) и (3) стопка (4) аккуратно сложенных (5) бумаг."
[🛑 Закончить]
```

**Пунктуация, верный ответ** (ввод `12`, эталон — `12`):
```
✅ Верно!

Правильно: На столе лежала книга, написанная известным автором, и стопка аккуратно сложенных бумаг.
[📖 Подробнее] [➡️ Следующее] [🛑 Закончить]
```

**Пунктуация, ошибка** (ввод `124`, эталон — `12`):
```
❌ Ошибка!

Правильно: На столе лежала книга, написанная известным автором, и стопка аккуратно сложенных бумаг.
```

## 13. Известные ограничения

- Собственного API и мини-приложения нет: проверка возможна только внутри мессенджера MAX. Файлы `openapi.yaml` и `DATA-API.yaml` не применимы.
- Сессия тренировки хранится в памяти процесса: перезапуск контейнера обрывает текущую тренировку, её нужно начать заново. Архитектура рассчитана на один экземпляр бота — при горизонтальном масштабировании на несколько реплик сессии не разделяются.
- Тренировка по орфоэпии и словарным словам не имеет ограничения длины: сессия содержит все элементы соответственно.
- Ввод позиций в пунктуации однозначный: номер позиции `0` указать нельзя, позиций больше девяти одновременно передать нельзя.
- Ударение определяется по заглавной гласной в слове; при отсутствии гласных предлагается единственный вариант.
- Пункт «📕 Мои сложные …» показывает не более 10 элементов; счётчик ошибок по каждому элементу не ведётся.
- История ответов не сохраняется: в базе хранится только агрегированный вес элемента, без привязки к датам, попыткам и сессиям.
- Данные — подготовленные дампы, реальные интеграции с государственными и отраслевыми системами не выполняются.
- Автоматических тестов в репозитории нет; проверка выполняется вручную по разделу 11.
- Сборка требует доступа к реестру npm и базовым образам; первый запуск с их загрузкой не входит в лимит 5 минут.
- Резервное копирование не входит в основной `docker-compose.yml` — оно доступно только в `docker-compose.prod.yml`.

## 14. Остановка и повторный запуск

Остановка с сохранением данных:
```bash
docker compose stop
```

Полное удаление контейнеров и сети (том `postgres_data` сохраняется):
```bash
docker compose down
```

Удаление вместе с данными (дампы применятся заново при следующем старте):
```bash
docker compose down -v
```

Повторный запуск без пересборки:
```bash
docker compose up -d
```

Пересборка образа после изменений в коде:
```bash
docker compose up -d --build
```

Запуск с резервным копированием:
```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Все сервисы объявлены с `restart: unless-stopped`, поэтому после перезагрузки хоста они стартуют автоматически. Миграции и автоинициализация данных при повторном запуске идемпотентны: повторного применения миграций и дампов на существующем томе не происходит.
